인수인계 승인과 Agent 조회 연결 — 2026-11-03, 미배포

기존 흐름: 원이정 요청 -> 김지수 승인 -> 승인된 Work 조회.
기존 요청/승인 API, DB 테이블, 화면 디자인은 변경하지 않았습니다.
공통 계정/선택 사용자 전용 Agent 데모 경로도 다시 추가하지 않았습니다.

Agent 연결
- 기존 직접 Task 역할을 가진 사용자의 조회는 유지합니다.
- 직접 역할이 없는 수신자는 서버에서 Task의 부모 Work를 조회합니다.
- 부모가 정확히 하나일 때 기존 demo_frontend._handover_db 읽기 함수를 재사용합니다.
- handover_requests에서 requester_id=검증된 세션 사용자,
  work_id=해당 부모 Work, status=approved인 기록이 있어야 허용합니다.
- 승인 기록은 질문마다 다시 확인하며 캐시하지 않습니다.
- 이후 해당 Task에 직접 연결된 Slack 원문만 조회하고 LLM에 전달합니다.
- 대기/거절/타인/다른 Work/부모 불명확은 업무 카드·원문 조회 전에 거부합니다.
- 승인 DB 장애 시 우회하지 않으며 LLM도 호출하지 않습니다.

검증
- Python 40개 테스트와 Node 질문 UI 검사 통과.
- 모의 저장소에서 pending -> approved -> rejected 전환의 차단/허용/차단 확인.
- 실제 Supabase 스키마 및 승인 기록을 읽기 전용으로 대조했습니다.
  approved 기록 3개, 승인 Work에 연결된 base Task 4개 / mock Task 15개 관측.
- DB 기록 생성/변경 및 운영 배포는 하지 않았습니다.

실행 조건과 남은 확인
- /api/chat/db는 기존 인증과 검증된 Slack 사용자 세션을 계속 요구합니다.
  공통 계정의 화면 사용자 선택만으로 개인을 인증하지 않습니다.
- 실제 사이트에서 사용하는 세션과 데이터셋(base/mock)을 맞춘 뒤
  로그인 -> 요청 -> 승인 -> 질문 -> 실시간 DB -> LLM -> UI 전체 검증이 필요합니다.
- 이 검증은 모의 승인/모델과 실제 DB의 읽기 대조이며 운영 종단 간 검증은 아닙니다.
- 기존 로컬 미리보기는 복사본 역할 실험입니다. 운영 승인 DB에 접근하지 않습니다.
